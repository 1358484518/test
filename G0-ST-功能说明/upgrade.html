4. 下载状态机 do_firmware_update

这个状态在 RAM 里，掉电丢失。每进函数推进一步。返回值大于 0 表示还要继续，0 表示成功，小于 0 表示失败。

状态动作失败码
0解析主机、端口、路径。https 则置 TLS，并先释放第二路 OCPP 的 TLS。置 fw_update=1、esp_irq_fiter_stop=1，避免串口把下载字节当 AT 应答。灯还没改-1 URL 解析失败
1每 200 次调用连一次服务器。连上后延时 200 ms，灯改红灯常亮，组 HTTP GET-2 尝试超过 600 次仍失败
2把 GET 发出去。失败再发一次-3 两次都发不出去
3，还没收到头收满 1024 字节后必须同时有 HTTP/1.1 200、Content-Length:、\r\n\r\n。整包长度必须在 10KB～512KB。空行后是自定义头：文件长度不超过 512KB 且不大于 HTTP 长度；类型必须是主控类型或 9-4 接收检查失败；-5 头不齐；-6 长度越界；-7 头长度非法；-8 类型不对
3，头已收到凑满 1024 字节就做 CRC16，签名升级再 sha256_update，DEV_W25X_Write 到当前地址，地址加 1024。写的时候红灯亮，写完灭接收中途失败同样 -4
收满断开网络。签名升级先验 SHA256，失败 -10。再比文件头 CRC 和算出的 CRC-10 签名失败
CRC 结果动作上层怎么报
文件头 CRC 等于计算出的 CRC，且签名通过或不是签名升级写完成结构到 0x00000000：标志 0x1234ABCD，长度用头里的 4 字节大端长度，名字 App.bin，CRC 用头里的值。置 system_dealy_reboot。从机标志清 0返回 0。状态改 Downloaded 并上报。fw_update_state 普通升级写 1，签名升级写 11。取消不可用
CRC 不相等，但签名已经通过不写主控完成标志。update_master_or_slave = 1，从机状态置 1函数仍返回 0，所以上层同样上报 Downloaded

类型 9 时期望地址是 0x080F0000，但写入语句统一是 DEV_W25X_Write，内部 Flash 的 InsideFlash_Write 被注释掉了。

应用不搬程序。Boot 看到 0x1234ABCD 才把下载区拷进内部 Flash。若 Boot 把 fw_update_state 写成 2/3 或 12/13，应用下次上电按第 3 节上报安装成功或失败。

5. 网页升级

步骤条件动作
拒绝Content-Length ≤ 10KB，或找不到头尾空行直接 return
跳过头正文前两字节是 0xFF 0xFF再跳过 10 字节
第一包—从 0x00001000 写入，桩设为不可用，红灯闪
后续包30 秒没有任何数据取消不可用并退出，不写完成标志
收齐对已写入的长度再算 CRC，结果是 0xFFFF当失败，取消不可用
成功CRC 不是 0xFFFF写 0x1234ABCD、长度、CRC、名字 App.bin。白灯常亮。页面提示约 10 秒后重启，置 system_reboot

6. 下载过程中桩的其它行为

对象行为
充电unavailable_enable = 1，等待态会进入不可用，从而不再启动
OCPP 主动报文进入 Downloading 时清心跳标志。发送函数里，下载中只放行固件状态和 StatusNotification
WiFi 串口esp_irq_fiter_stop = 1，AT 解析暂停，避免和 HTTP 字节混在一起
灯OCPP 下载：连接后红灯常亮，每写 1024 字节灭一次。网页：红灯闪，成功后白灯常亮
第二路 TLShttps 下载开始时若第二路还连着，先 tls_free
